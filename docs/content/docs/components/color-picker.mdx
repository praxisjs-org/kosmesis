## About

Purely presentational — no Morphos equivalent. Unlike `DatePicker`, `ColorPicker` owns its
[Popover](/docs/components/popover) instance internally rather than taking one as a prop — there's
no reason a consumer would need to share it with a sibling component. `value`/`defaultValue` only
seed the initial color: HSV, not the emitted hex string, is the source of truth for the widget
after that. Round-tripping a controlled value back through hex on every change would reset hue
whenever saturation or value passes through 0 (hue is undefined for grayscale), which is why
`onChange` is the way to observe changes rather than feeding `value` back in on every keystroke.

The saturation/value area, hue track, and alpha track are all plain `role="slider"` `div`s driven
by pointer position relative to their own bounding rect (same technique as `Sortable` and
`Comparison`) — arrow keys work once one is focused.

## Usage

```tsx
import { ColorPicker } from "@/components/ui/color-picker";

<ColorPicker
  defaultValue="#3b82f6"
  onChange={(value) => console.log(value)}
/>
```
