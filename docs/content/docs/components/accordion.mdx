## Usage

```tsx
import { Accordion, AccordionContent, AccordionItem, AccordionTrigger } from "@/components/ui/accordion";

@Component()
class FaqAccordion extends StatefulComponent {
  @State() accordion = new Accordion({ type: "single", collapsible: true });

  render() {
    return (
      <Accordion type="single" collapsible class="w-full max-w-md">
        <AccordionItem accordion={this.accordion} value="item-1">
          <AccordionTrigger accordion={this.accordion} item="item-1">
            Is it accessible?
          </AccordionTrigger>
          <AccordionContent accordion={this.accordion} item="item-1">
            Yes. It adheres to the WAI-ARIA design pattern.
          </AccordionContent>
        </AccordionItem>
      </Accordion>
    );
  }
}
```

<Callout type="info">
  `<Accordion>` mounted in the tree and `this.accordion` are two separate objects — see the note
  on [Radio Group](/docs/components/radio-group). Keep `type`/`collapsible` in sync between them.
</Callout>

## Props

### Accordion

| Prop | Type | Default |
|---|---|---|
| `type` | `"single" \| "multiple"` | `"single"` |
| `collapsible` | `boolean` | `true` — only relevant when `type="single"` |
| `value` | `string \| string[]` | — controlled open value(s) |
| `defaultValue` | `string \| string[]` | — |
| `onValueChange` | `(value: string \| string[]) => void` | — |

### AccordionItem

| Prop | Type | Default |
|---|---|---|
| `accordion` | `Accordion` | — required, the state instance from `@State()` |
| `value` | `string` | — required |
| `disabled` | `boolean` | — |

### AccordionTrigger

| Prop | Type | Default |
|---|---|---|
| `accordion` | `Accordion` | — required |
| `item` | `string` | — required, matching the parent `AccordionItem`'s `value` |

### AccordionContent

| Prop | Type | Default |
|---|---|---|
| `accordion` | `Accordion` | — required |
| `item` | `string` | — required, matching the parent `AccordionItem`'s `value` |
